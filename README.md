# 各说各话

> 同一出戏，各地各演一遍。

**线上：https://geshuo.pages.dev**

一个方言场景剧场：把「深夜回家被妈妈盘问」这样的日常场景写成一副**只描述情节、不含台词**的骨架，让各地方言各自填肉，然后逐拍对齐——于是你可以横着听过去，看同一句质问在德州、广州、成都、沈阳分别是怎么说出口的。

```
第 1 拍 · 妈妈质问几点了

冀鲁官话  这都多咱了才家来？你还知道恁家门朝哪开啊？
粤语      而家几点啦你先返嚟？你仲知唔知返屋企条路点行啊？
成渝片    都几点了才晓得回来？你还晓得屋头门朝哪边开不？
东北官话  这都几点了才知道回来？你还知道咱家门朝哪开呢？
```

## 为什么再做一个方言站

[语言资源保护工程](https://zhongguoyuyan.cn/)有 1284 个汉语方言调查点，[乡音苑](https://phonemica.net/)众包了十五年的方言故事——**档案馆的位置已经有人占了，而且做得比我们能做的更全**。

这个项目做的是**剧场**：差异不在收录量，在**可对比性**。前两者的语料没有共同骨架，所以你没法把「妈妈爆发」这一拍横着并排听。而这恰恰是最能让人一下子听懂「方言差在哪」的方式——不是听一段陌生的故事，是听一句你完全知道该说什么的话，被别人用另一种方式说出来。

## 三条不肯让步的设计

**一、不存在「山东话」这个节点。**

山东跨冀鲁官话、中原官话、胶辽官话三个官话区。德州人和青岛人说方言，「慢了还好说，快了可能得捎上个翻译」。把它们合并成一个笼统标签，等于向德州人播放胶东腔并声称那是他的话。

方言树按《中国语言地图集》的五层分区建模：**大区 — 区 — 片 — 小片 — 点**，德州与青岛是分属不同区的独立节点，有测试钉着。

**二、AI 合成的语音，禁止挂到县市级。**

模型给不出县域口音。所以 TTS 演绎只能挂在「区」或「片」这样的粗颗粒上，挂到「点」级会被构建期硬拦截——那不是保守，那是虚假标注。页面上也必须明写「这是区级合成语音，不代表任何具体县市」。

**这个粒度差是引擎，不是缺陷。** 你听着别扭是对的，旁边就有一个按钮请你录一个真的。每来一份真人录音，方言树就往下长出一个更细的叶子；网站的成长方式，就是这棵树从「区」向「点」不断加密。

**三、三档可信度必须一眼可辨。**

`AI 未校对` / `AI 已经母语者校对` / `真人录音`——三档在任何页面上都不许塌成两档。标签文字和样式统一从一处取值，不允许某个页面自己重新判断一份。

因为**假台词比假口音更伤**：口音不准还能推给技术限制，措辞不地道是硬伤，母语者一眼看穿，然后整个站的可信度就没了。

## 现状：引擎完备，内容才刚开头

- 4 个方言演绎，**全部标注为「AI 生成 · 未经母语者校对」**

这不是谦虚，是这个站的默认状态：**先给一个粗糙的版本，再等老乡来纠正。**

## 跑起来

需要 Node ≥ 22.12 和 pnpm。

```bash
pnpm install
pnpm dev            # http://localhost:4321
pnpm test           # 52 个测试
pnpm check          # 类型检查
```

### 生成语音（可选）

仓库里**不包含音频文件**——它们是可再生的构建产物，而且 AI 生成内容的权属条款目前不够清晰，不适合随开源项目分发。你可以用自己的 [阿里云百炼](https://bailian.console.aliyun.com/) API key 生成：

```bash
echo 'DASHSCOPE_API_KEY=sk-你的key' > .env
pnpm gen:audio -- late-night.chengyu
```

音频落到 `public/audio/`，路径回填进演绎 YAML。四个方言全跑一遍约 650 计费字符，**六分五厘钱**；新账号的免费额度绰绰有余。

各方言走的模型与音色（均经真实 API 验证）：

| 方言 | 模型 | 音色 |
|---|---|---|
| 成渝片 | `qwen3-tts-flash` | `Sunny` |
| 粤语 | `qwen3-tts-flash` | `Rocky` |
| 冀鲁官话 | `cosyvoice-v3-flash` | `longanhuan_v3` + instruct「请用山东话表达」 |
| 东北官话 | `cosyvoice-v3-flash` | `longlaotie_v3` |

胶辽官话（青岛）**故意留空**：CosyVoice 音色表里没有胶辽专属音色，而「山东话」这个 instruct 大类能否准确覆盖胶东口音，得真人听测才能下结论，代码不该替人假设。

## 一起来填

最想要的三种贡献，按门槛从低到高：

**挑错。** 哪一句不地道，开个 issue 说「俺们那儿不这么说，说的是 XX」。这是最有价值的贡献——每一条都能把一份 AI 台词从「未校对」升成「已校对」。

**加方言。** 照 `src/data/performances/late-night.jilu.yaml` 的样子写一份，六拍齐全，配上普通话直译和用词注释。**只写你自己会说的方言**——这个项目宁可少一个方言，也不要一份塑料方言。

**加场景。** 在 `src/data/scenes/` 写一副新骨架。骨架只描述情节意图（「妈妈翻旧账」），绝不写具体台词。菜市场砍价、亲戚劝婚、跟爸妈解释为什么还不买房——越是全国人民都经历过的，对比起来越有意思。

细则见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 技术栈

Astro 7 静态站，无数据库——方言树、场景、演绎全部是构建时读取的 YAML。语音一次性生成后静态托管，页面播放不调任何 API。

```
src/data/          方言树、场景骨架、各地演绎（YAML）
src/lib/           数据加载与构建期完整性校验
src/components/    剪纸窗、台词卡、方言切换
scripts/gen/       台词生成（词表约束）、语音合成
```

`src/lib/content.ts` 的 `validateContent()` 是这个项目的安全带：漏一拍、多一拍、挂错方言层级、可信度写错枚举——全部在构建期炸掉，不给坏数据静静上线的机会。

## 部署

站点在 Cloudflare Pages，走 **wrangler 直传**，不是 git 集成：

```bash
pnpm deploy    # astro build && wrangler pages deploy dist
```

之所以不接 git 自动部署：**音频不在仓库里**。CF 从 GitHub 拉代码构建，产出的会是一个哑巴站——而语音恰恰是这个项目的全部意义。所以部署必须从一台本地有 `public/audio/` 的机器发起。

这意味着**合进 main 不等于上线**。改了台词也要有人重新跑一次 `pnpm deploy`。
